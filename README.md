# Cookie POS — Offline-First iPad POS (PWA)

ระบบขายหน้าร้านสำหรับ iPad ที่ทำงานได้ **100% แม้ไม่มีอินเทอร์เน็ต** โฮสต์ฟรีบน **Cloudflare Pages** หลังระบบ Login (อีเมล + รหัส OTP) และ Sync บิลไปที่ **Google Sheets** ผ่านตัวกลางที่ปลอดภัย (`/api/sync`) อัตโนมัติเมื่อออนไลน์

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | โครงหน้าจอ (Top bar, เมนู 70%, ตะกร้า 30%, Modals ทั้งหมด) |
| `styles.css` | ธีม Burgundy `#862d28` / Cream `#f7f0dd` + สไตล์สำหรับจอสัมผัส (ทำงานได้แม้ Tailwind CDN โหลดไม่ได้) |
| `app.js` | State, ตะกร้า, ชำระเงิน, ตัด/คืนสต็อก, จัดการเมนู, คิว Sync, Backup (บิลเก็บใน IndexedDB) |
| `promo.js` | **Promo Engine** — กฎโปรแบบยืดหยุ่น 4 แบบ + หน้าตั้งค่าโปร + ตัวเลือกโปรของพนักงาน |
| `features.js` | พนักงาน/PIN/สิทธิ์ · หมายเหตุ · พักบิล · QR พร้อมเพย์ · ใบเสร็จ · กะ & ลิ้นชักเงินสด · สมาชิก/แต้ม · ประวัติสต็อก · รายงาน |
| `kds.js` | จอจัดออเดอร์หลังร้าน (Kitchen Display) สำหรับ iPad เครื่องที่ 2 |
| `vendor/qrcode.min.js` | ตัวสร้าง QR (qrcode-generator 1.4.4, MIT) — ฝังในแอป ใช้งานออฟไลน์ได้ |
| `sw.js` | Service Worker — Network-First / Cache-Fallback |
| `manifest.json` | PWA manifest (standalone, landscape) |
| `icons/` | ไอคอนแอป (192, 512, apple-touch-icon) |
| `google-apps-script.gs` | โค้ดฝั่ง Google Sheets (`doPost` / `doGet`) — รับเฉพาะคำขอที่มีรหัสลับ |
| `functions/api/sync.js` | Cloudflare Pages Function: ตรวจ Login (Cloudflare Access) แล้วส่งต่อไป Apps Script พร้อมรหัสลับ |
| `_headers` | ให้ Cloudflare ไม่ cache `index.html` / `sw.js` (อัปเดตแอปได้ทันที) |

ไม่ต้อง build ไม่ต้องติดตั้ง npm — push ขึ้น GitHub แล้ว Cloudflare Pages deploy ให้อัตโนมัติ

## 1. Deploy ขึ้น Cloudflare Pages + Login (อีเมล OTP)

```
iPad ──(Login: อีเมล + OTP — Cloudflare Access)──▶ https://<โปรเจกต์>.pages.dev ──▶ /api/sync ──(+ รหัสลับ)──▶ Google Apps Script ──▶ Google Sheets
```
- ใครไม่ได้ Login ด้วยอีเมลที่อนุญาต จะเปิดแอปไม่ได้และเรียก `/api/sync` ไม่ได้
- URL ของ Apps Script และรหัสลับเก็บใน Cloudflare เท่านั้น ไม่อยู่ใน iPad · คนที่ได้ URL `/exec` ไปก็ใช้ไม่ได้เพราะไม่มีรหัสลับ
- PIN พนักงานในแอปยังใช้เหมือนเดิม (Login = เข้าแอปได้ไหม · PIN = ในแอปทำอะไรได้)

### 1.0 ย้ายมาจาก GitHub Pages? ทำข้อนี้ก่อน ⚠️
โดเมนใหม่ = พื้นที่เก็บข้อมูลใหม่ (บิล สต็อก ตั้งค่าใน iPad **ไม่ตามมาเอง**) ทำบน **ทุกเครื่อง** ที่เว็บเดิม (github.io):
1. ตั้งค่า ▸ Cloud Sync ▸ กด **Sync ข้อมูลทั้งหมดตอนนี้** จนคิวรอ Sync = 0
2. ตั้งค่า ▸ สำรอง & บำรุงรักษา ▸ **Export Backup (JSON)** ▸ เก็บไฟล์ไว้ (Files / AirDrop)
> ต้องทำก่อนข้อ 1.1 ข้อ 3 เพราะเมื่อตั้งรหัสลับแล้ว เว็บเดิมจะส่งข้อมูลขึ้น Sheets ไม่ได้อีก

### 1.1 Google Apps Script — ตั้งรหัสลับ
1. เปิด Google Sheet ▸ Extensions ▸ Apps Script ▸ วางโค้ด `google-apps-script.gs` ล่าสุดทับ ▸ Save
2. เลือกฟังก์ชัน `setup` ▸ ▶ Run (ครั้งแรกให้อนุญาตสิทธิ์)
3. เลือกฟังก์ชัน `createSyncSecret` ▸ ▶ Run ▸ เปิด **Execution log** ▸ คัดลอกค่าหลัง `SYNC_SECRET =` (เก็บไว้ใช้ในข้อ 1.4)
4. **Deploy ▸ Manage deployments ▸ ✏️ ▸ Version: New version ▸ Deploy** (ยังเป็น Who has access: Anyone ได้ — มีรหัสลับคุมอยู่แล้ว) ▸ คัดลอก Web app URL (`.../exec`)

### 1.2 สร้างเว็บบน Cloudflare Pages
1. push โค้ดนี้ขึ้น GitHub repo ของร้าน (Private ได้)
2. https://dash.cloudflare.com ▸ **Workers & Pages** ▸ Create ▸ แท็บ **Pages** ▸ **Connect to Git / Import an existing Git repository** ▸ เลือก repo
3. Framework preset: **None** · Build command: **เว้นว่าง** · Build output directory: **`/`** ▸ Save and Deploy
4. จะได้ URL `https://<ชื่อโปรเจกต์>.pages.dev` (ยังไม่ต้องเปิดใช้งาน — ทำ 1.3 ก่อน)

### 1.3 Cloudflare Access — Login ด้วยอีเมล + OTP
1. Dashboard ▸ **Zero Trust** (ครั้งแรกตั้งชื่อทีม เช่น `maysa` → ได้ `maysa.cloudflareaccess.com` · เลือกแพ็กเกจ **Free** — ใช้ได้ถึง 50 คน)
2. Settings ▸ Authentication ▸ Login methods ▸ ตรวจว่ามี **One-time PIN** (เปิดอยู่แล้วโดยค่าเริ่มต้น)
3. Access ▸ Applications ▸ **Add an application ▸ Self-hosted**
   - Application name: `POS` · **Session Duration: 1 month** (iPad ไม่ต้อง Login บ่อย — ตั้งสั้นลงได้)
   - Domain: `<ชื่อโปรเจกต์>.pages.dev` และเพิ่มอีกบรรทัด `*.<ชื่อโปรเจกต์>.pages.dev` (ปิด URL ทดสอบ/preview ด้วย)
   - Policy: Action **Allow** · Include ▸ **Emails** ▸ ใส่อีเมลเจ้าของร้านและพนักงานที่อนุญาต (เพิ่ม/ลบภายหลังได้)
   - Save
4. เปิดแอปที่สร้าง ▸ แท็บ Overview ▸ คัดลอก **Application Audience (AUD) Tag**

### 1.4 ใส่ค่าลับใน Cloudflare Pages
โปรเจกต์ Pages ▸ **Settings ▸ Variables and Secrets** (Production) ▸ Add:

| ชื่อ | ค่า | ประเภท |
|---|---|---|
| `GAS_URL` | Web app URL จากข้อ 1.1 (`https://script.google.com/macros/s/.../exec`) | Secret |
| `SYNC_SECRET` | ค่าจาก `createSyncSecret` | Secret |
| `ACCESS_TEAM_DOMAIN` | `maysa.cloudflareaccess.com` (ชื่อทีมของคุณ) | Text |
| `ACCESS_AUD` | AUD Tag จากข้อ 1.3 | Text |

แล้วไปที่ **Deployments ▸ ⋯ ▸ Retry deployment** (ค่าใหม่มีผลหลัง deploy ใหม่)

### 1.5 ติดตั้งบน iPad + นำข้อมูลเดิมกลับ
1. Safari ▸ เปิด `https://<ชื่อโปรเจกต์>.pages.dev` ▸ ใส่อีเมล ▸ ใส่รหัส 6 หลักที่ได้ทางอีเมล
2. แชร์ ▸ **Add to Home Screen** ▸ เปิดแอปจากไอคอน ▸ **Login อีกครั้ง** (แอปบนหน้าโฮมแยกการ Login จาก Safari)
3. ตั้งค่า ▸ เครื่องนี้ ▸ ช่อง URL จะเป็น `/api/sync` อัตโนมัติ ▸ กด **ทดสอบ** ควรขึ้น “เชื่อมต่อสำเร็จ ✓”
4. ถ้าย้ายมาจากเว็บเดิม: ตั้งค่า ▸ สำรอง & บำรุงรักษา ▸ **Import Backup** ไฟล์จากข้อ 1.0 (URL ใน Backup จะถูกเปลี่ยนเป็น `/api/sync` ให้เอง)
5. ปิดเว็บเดิม: GitHub repo ▸ Settings ▸ Pages ▸ **Unpublish** (และตั้ง repo เป็น Private ได้)

### เมื่อ Session หมดอายุ
- แอปยัง **ขายได้ตามปกติ** (ทำงานออฟไลน์ได้อยู่แล้ว) บิลและตะกร้าเก็บในเครื่องครบ
- ด้านบนจะขึ้น **แถบสีแดง “เซสชันเข้าสู่ระบบหมดอายุ”** พร้อมปุ่ม **รีเฟรชเพื่อ Login ใหม่** → กด ▸ ใส่อีเมล + OTP ▸ แอปส่งบิลที่ค้างขึ้น Sheets ให้อัตโนมัติ
- จอครัว (KDS) จะแสดงแถบเดียวกัน
- ระบบ **ไม่** นับว่าบิลส่งสำเร็จระหว่างที่ Session หมดอายุ (บิลอยู่ในคิวจนกว่าจะส่งได้จริง)

## 2. ติดตั้งบน iPad

1. เปิด URL ด้วย **Safari** (ต้องออนไลน์ในครั้งแรก เพื่อให้ Service Worker เก็บไฟล์ไว้ใช้ออฟไลน์)
2. กดปุ่ม **แชร์ (Share)** ▸ **เพิ่มไปยังหน้าจอโฮม (Add to Home Screen)**
3. เปิดแอปจากไอคอนบนหน้าจอโฮม → แอปจะเปิดแบบเต็มจอ แนวนอน
4. แนะนำ: เปิดแอปค้างไว้สักครู่ขณะออนไลน์ แล้วลองเปิด **โหมดเครื่องบิน** เพื่อทดสอบว่าใช้งานออฟไลน์ได้

## 3. ตั้งค่า Google Sheets Sync

1. สร้าง Google Sheet ใหม่ (เช่น ชื่อ `Cookie POS Orders`)
2. เมนู **Extensions (ส่วนขยาย) ▸ Apps Script**
3. ลบโค้ดเดิมใน `Code.gs` ทั้งหมด แล้ววางโค้ดจากไฟล์ `google-apps-script.gs` ▸ กด **Save** 💾
4. เลือกฟังก์ชัน `setup` ในแถบด้านบน ▸ กด **▶ Run** ▸ อนุญาตสิทธิ์ (Review permissions ▸ เลือกบัญชี ▸ Advanced ▸ Go to project ▸ Allow)
   → จะเกิดชีต `Orders`, `Order_Items`, `Sync_Log` อัตโนมัติ
5. (ไม่บังคับ) เลือกฟังก์ชัน `testPost` ▸ Run เพื่อทดสอบ — จะมีบิล `ORD-TEST-...` สถานะ `VOIDED` ปรากฏในชีต (ลบทิ้งได้)
6. กด **Deploy ▸ New deployment** ▸ ไอคอนเฟือง ▸ เลือก **Web app**
   - Description: `POS Sync`
   - Execute as: **Me**
   - Who has access: **Anyone** ← สำคัญ (ถ้าเลือกอย่างอื่น iPad จะส่งข้อมูลไม่ได้)
7. กด **Deploy** ▸ คัดลอก **Web app URL** (ลงท้ายด้วย `/exec`)
8. **บน Cloudflare:** ไม่ต้องวาง URL ในแอป — ใส่ URL นี้ใน Cloudflare เป็น `GAS_URL` (ข้อ 1.4) แอปใช้ `/api/sync` อัตโนมัติ ▸ กด **ทดสอบ** ควรขึ้น "เชื่อมต่อสำเร็จ ✓"
   (ถ้าลบ `<meta name="pos-sync-url">` ออกจาก `index.html` แอปจะกลับไปส่งตรงถึง Apps Script แบบเดิม)

> **อัปเกรดเป็น v3:** วางโค้ด `google-apps-script.gs` ใหม่ทับ ▸ Save ▸ Run `setup` 1 ครั้ง ▸ **Manage deployments ▸ ✏️ ▸ Version: New version ▸ Deploy**
> ชีต `Orders` / `Order_Items` เดิมถูก **เพิ่มคอลัมน์ต่อท้าย** (ข้อมูลเดิมไม่หาย) และสร้างชีตใหม่ `Shifts`, `Cash_Moves`, `Stock_Log`, `Customers` ให้อัตโนมัติ

### การแก้ไขโค้ด Apps Script ภายหลัง
ถ้าแก้โค้ด `.gs` ต้อง **Deploy ▸ Manage deployments ▸ ✏️ Edit ▸ Version: New version ▸ Deploy** เพื่อให้ URL เดิมใช้โค้ดใหม่ (ไม่ต้องเปลี่ยน URL ในแอป)

> **อัปเกรดจาก v1:** วางโค้ด `google-apps-script.gs` ใหม่ทับของเดิม ▸ Save ▸ Run `setup` 1 ครั้ง ▸ **Manage deployments ▸ ✏️ ▸ Version: New version ▸ Deploy** (URL เดิมใช้ต่อได้)
> ชีต `Orders` เดิมจะถูกเพิ่มคอลัมน์ `Payment_Key` ต่อท้ายโดยข้อมูลเดิมไม่หาย · ชีต `Order_Items` เดิม (คอลัมน์ต่างจากเวอร์ชันใหม่) จะถูกเปลี่ยนชื่อเป็น `Order_Items_old_<วันที่>` เก็บไว้ แล้วสร้างชีตใหม่

### โครงสร้างชีต
- **Orders** — 1 แถว/บิล: `Order_ID, Status (COMPLETED/VOIDED), Date, Date_Time, Timestamp_ISO, Items_Detail, Subtotal, Promo_Discount, Promo_Detail, Item_Discount, Manual_Discount, Total_Discount, Net_Total, Payment_Method, Cash_Received, Change, Device, Voided_At, Void_Reason, Synced_At, Payment_Key`
- **Order_Items** — 1 แถว/รายการสินค้า (น้ำหนักขาย/แถม, `Options`, `Add_Ons`) เหมาะสำหรับทำ Pivot Table ยอดขายรายเมนู
- **App_State** — ข้อมูลกลางของทุกเครื่อง: `catalog` (เมนู/หมวด/โปร/Stock Pool), `stock`, `settings` (ชื่อร้าน) — `Key, Updated_At, Updated_By_Device, JSON_Value…`
- **Menu_Images** — รูปเมนู 1 แถว/เมนู (`Item_ID, Updated_At, Updated_By_Device, Chars, Base64_Data…`)
- **Sync_Log** — บันทึกทุกครั้งที่มีการส่งข้อมูล (เก็บล่าสุด 2,000 แถว)
- **v3 คอลัมน์เพิ่มใน Orders** — `Queue_No, Order_Note, Kitchen_Status (PENDING/DONE/VOIDED/NONE), Kitchen_Items (JSON สำหรับ KDS), Kitchen_Updated_At, Staff, Customer_Phone, Customer_Name, Points_Earned, Points_Redeemed, Points_Discount, Total_Cost, Shift_ID, Manual_By, Voided_By`
- **v3 คอลัมน์เพิ่มใน Order_Items** — `Line_Note, Promo_Discount, Cost, Staff`
- **Shifts** — 1 แถว/กะ: เงินทอนตั้งต้น, ยอดขาย, เงินสดที่ควรมี, นับได้จริง, ส่วนต่าง (ขาด = ตัวแดง)
- **Cash_Moves** — เงินเข้า/ออกระหว่างกะ (Pay-in / Pay-out) พร้อมเหตุผลและผู้ทำ
- **Stock_Log** — ทุกการปรับสต็อก: ก่อน → หลัง, เหตุผล (เติมสต็อก / ของเสีย / แจกฟรี …), มูลค่าต้นทุน
- **Customers** — สมาชิก: `Phone, Name, Points, Visits, Total_Spent, First_Visit, Last_Visit` (แต้มอัปเดตจากบิลบน Server — ไม่ซ้ำแม้ส่งซ้ำ)

ข้อมูลยาว ๆ ถูกแบ่งเป็นช่วงละ ≤ 45,000 ตัวอักษรในหลายคอลัมน์ จึงไม่ชนลิมิต 50,000 ตัวอักษร/เซลล์ของ Google Sheets
การส่งซ้ำ (retry) **ไม่ทำให้บิลซ้ำและไม่ตัดสต็อกซ้ำ** เพราะสคริปต์ค้นหา `Order_ID` ก่อนเสมอ (upsert)

## 4. การใช้งาน

### หน้าขาย
- แตะการ์ดเมนูเพื่อเพิ่มลงตะกร้า — ป้ายมุมขวาบนแสดงสต็อก**ที่ยังขายได้** (หักของที่อยู่ในตะกร้าแล้ว)
- สต็อกหมด → ขึ้น **SOLD OUT** และกดไม่ได้ (เมนูขายตามน้ำหนัก: เมื่อเหลือน้อยกว่าขั้นต่ำ)
- เมนู **ขายตามน้ำหนัก** (เช่น ซีเรียลคุกกี้) เปิดหน้าต่างชั่งน้ำหนัก: น้ำหนักขาย, น้ำหนักแถม (ฟรี แต่ตัดสต็อก), ส่วนลดรายการ — แตะช่องเพื่อเลือก แล้วพิมพ์ด้วย numpad
- เมนู **เซ็ต + ตัวเลือก** (เช่น Gooey Chocolate + Ice Cream) เลือกตัวเลือกบังคับ + Add-on + จำนวนเซ็ต
- แก้ไขรายการขายตามน้ำหนัก/เซ็ตในตะกร้าได้ด้วยปุ่ม ✏️

### โปรโมชั่น (Flexible Promo Engine) — จัดการเมนู ▸ โปรโมชั่น
ตั้งโปรเองได้ทั้งหมดโดยไม่ต้องแก้โค้ด เลือกสินค้าได้ทั้ง “ทุกเมนู / ทั้งหมวด / รายเมนู” และ “ยกเว้น” รายเมนู — สินค้าชิ้นเดียวอยู่ได้หลายโปร

| ประเภท | ตัวอย่าง |
|---|---|
| **จับเซ็ต / Bundle** (ข้ามหมวดได้ หลายช่อง) | ซอฟต์คุกกี้ 3 ชิ้น 100฿ · คุกกี้ 2 + เครื่องดื่ม 1 = 120฿ · ลด 15% เมื่อซื้อครบชุด |
| **ลดราคาต่อชิ้น** | ทั้งหมวดลด 10% · ลด 5฿/ชิ้น เมื่อซื้อ ≥ 4 · ราคาพิเศษ 29฿ |
| **ซื้อ X แถม Y** | ซื้อ 2 แถม 1 (ชิ้นถูกสุดฟรี) · ซื้อคุกกี้ 3 ได้ชูครีมลด 50% |
| **ยอดซื้อขั้นต่ำ** | ครบ 300฿ ลด 30฿ · ครบ 500฿ ลด 10% · ครบ 200฿ แถมชูครีม 1 ชิ้น (ทบได้) |

- ตั้ง **ช่วงเวลา** ได้ (วันในสัปดาห์, เวลา เช่น Happy Hour 15:00–17:00, วันเริ่ม/สิ้นสุด), **เฉพาะสมาชิก**, **จำกัดครั้ง/บิล**
- **ลำดับความสำคัญ** = ลำดับในรายการ (ลากขึ้น/ลง) — สินค้าที่เข้าได้หลายโปรจะถูกใช้กับโปรลำดับบนก่อน
- หน้าร้าน: กดปุ่ม **🏷 โปรโมชั่น** ในตะกร้า → พนักงานปิดโปรบางตัวในบิลนั้น หรือเลือก “ลูกค้าคุ้มที่สุด” ให้ระบบลองทุกแบบแล้วเลือกส่วนลดสูงสุด
- จับชุดจากชิ้นที่ราคาสูงสุดก่อน (ลูกค้าได้ส่วนลดมากที่สุด) · หน้าแก้ไขโปรมี “ทดสอบกับตะกร้าปัจจุบัน” ให้เห็นผลทันที

### ชำระเงิน
วิธีชำระเงินเพิ่ม/ซ่อน/เรียงได้ที่ **ตั้งค่า ▸ การชำระเงิน** · ใส่เบอร์พร้อมเพย์แล้ว **QR จะมียอดเงินในตัว** (สร้างในเครื่อง ไม่ต้องใช้เน็ต) · ใส่เบอร์สมาชิกเพื่อสะสม/ใช้แต้ม → ยืนยัน ระบบจะ
1. สร้างเลขบิล `ORD-<รหัสเครื่อง>-YYYYMMDD-XXX` (เช่น `ORD-IPAD1-20261114-001`) + เวลา ISO และ `DD/MM/YYYY HH:mm:ss`
2. ตัดสต็อกทุกรายการ (รวมกรัมที่แถม, สกู๊ปไอศกรีม, คุกกี้ Gooey)
3. บันทึกประวัติ + เข้าคิว Sync (ส่งทันทีถ้าออนไลน์)
4. แสดง **เลขคิว** ตัวใหญ่ (#01 เริ่มใหม่ทุกวัน) + ใบเสร็จ — กด **พิมพ์** (AirPrint / เครื่องพิมพ์ความร้อน 58 / 80 mm) หรือ **แชร์รูปใบเสร็จ** ทาง LINE / AirDrop

### ยกเลิกบิล (VOID)
**ประวัติบิล & สรุปยอดขาย** ▸ ปุ่ม **ยกเลิกบิล** → คืนสต็อกตามจำนวนที่ตัดไปจริงทุกหน่วย, ไม่นับในยอดขาย, ส่ง `VOID_ORDER` ไป Sheet (หรือเข้าคิวถ้าออฟไลน์)

### ปุ่ม Update App Version (🔄 มุมขวาบน)
ดาวน์โหลดไฟล์แอปเวอร์ชันล่าสุดจาก Cloudflare Pages แล้วรีโหลด — **ข้อมูลสต็อก บิล รูปภาพ ไม่หาย** (อยู่ใน localStorage / IndexedDB แยกจาก cache ของแอป)

> หลัง push โค้ดใหม่ขึ้น GitHub (Cloudflare deploy ให้อัตโนมัติ): เมื่อ iPad ออนไลน์ การเปิดแอปใหม่/กด Update จะได้เวอร์ชันล่าสุดทันที (Cloudflare Pages deploy เสร็จใน ~1 นาที ดูสถานะที่ Deployments)
> ถ้าแก้ `sw.js` ควรเปลี่ยน `SW_VERSION` ด้วย เพื่อให้ล้าง cache เก่า

## 5. ข้อมูลและการสำรองข้อมูล

| ข้อมูล | ที่เก็บ |
|---|---|
| เมนู/หมวด/โปร/พนักงาน/ตัวเลือกร้าน (`pos.v1.catalog`), สต็อก, คิว Sync, ตั้งค่า, ตะกร้า, บิลพัก, กะปัจจุบัน, สมาชิก | `localStorage` (key ขึ้นต้นด้วย `pos.v1.`) |
| **ประวัติบิล**, ประวัติสต็อก, ประวัติกะ | `IndexedDB` (`pos-data`) — เก็บได้หลายหมื่นบิล (ย้ายจาก localStorage ให้อัตโนมัติครั้งแรก) |
| รูปเมนู (JPEG 250×250 ≈ 15–25 KB/รูป) | `IndexedDB` (`pos-images`) |

> อัปเดตจาก v1: ครั้งแรกที่เปิด v2 ระบบสร้างเมนูชุดเดิม (รหัสเดิม) ให้อัตโนมัติ — สต็อก บิล และรูปเดิมใช้ต่อได้ทันที รูปเดิมที่ใหญ่เกินจะถูกย่อให้พอดีกับเซลล์ Google Sheets

- **Export Backup (JSON)** — ไฟล์เดียวรวมทุกอย่าง (รวมรูป) บน iPad ใช้ปุ่ม **แชร์ไฟล์ Backup** เพื่อบันทึกลง Files / AirDrop
- **Import Backup (JSON)** — แทนที่ข้อมูลทั้งหมดในเครื่อง (ใช้ย้ายเครื่อง/กู้คืน)
- บิลอยู่ใน IndexedDB แล้ว จึงไม่ชนลิมิต 5 MB ของ localStorage · ล้างบิลเก่าที่ Sync แล้ว (เกิน 365 วัน) ได้ในหน้าตั้งค่า (ข้อมูลยังอยู่ใน Google Sheets)
- ⚠️ iPadOS อาจลบข้อมูลเว็บแอปที่ไม่ได้เปิดใช้งานนานหลายสัปดาห์ — แอปขอ `navigator.storage.persist()` ไว้แล้ว แต่ควร Export Backup เป็นประจำ และอย่าลบ "ข้อมูลเว็บไซต์" ของ Safari

## 6. จัดการเมนู & สต็อก (แบบ GrabMerchant)

ปุ่ม **จัดการเมนู & สต็อก** ที่แถบด้านบน มี 4 แท็บ — ทุกการแก้ไขบันทึกทันที และส่งขึ้น Cloud อัตโนมัติ (ถ้าเปิดไว้)

| แท็บ | ทำอะไรได้ |
|---|---|
| **เมนู** | เพิ่ม/แก้ไข/ลบเมนู · สลับสถานะด่วน **เปิดขาย / หมดวันนี้ / ซ่อน** (“หมดวันนี้” กลับมาเปิดขายเองในวันถัดไป) |
| **หมวดหมู่** | เพิ่ม · เปลี่ยนชื่อ · เลื่อนขึ้น/ลง (= ลำดับแท็บหน้าขาย) · ซ่อน/แสดง · ลบ (เมื่อไม่มีเมนูในหมวด) · ตั้ง **โปรของหมวด** |
| **โปรโมชั่น** | โปรคละได้ “ครบ X ชิ้น = Y บาท” · เปิด/ปิด · ติ๊กเลือกเมนูที่ร่วมโปร · เพิ่มโปรใหม่ |
| **สต็อก** | ใส่จำนวนตรง ๆ หรือกด `-1 +5 +10` / `-100g +100g +500g` · เปลี่ยนชื่อ Stock Pool · สร้าง **Stock Pool ใช้ร่วม** (เช่น ไอศกรีมที่หลายเมนูใช้) |

**ฟอร์มเมนู:** ชื่อ · หมวดหมู่ · รูป (ย่อเป็น 250×250 JPEG อัตโนมัติ) · ป้ายบนการ์ด · รูปแบบการขาย 3 แบบ:
1. **ขายเป็นชิ้น** — ราคา/ชิ้น, ผูกสต็อก (ของเมนูเอง / Pool ใช้ร่วม / ไม่ตัดสต็อก), เลือกโปร (ตามหมวด / ไม่ร่วม / โปรเฉพาะ)
2. **ขายตามน้ำหนัก** — ราคา/กรัม, ขั้นต่ำ (กรัม), สต็อกเป็นกรัม — มีหน้าต่างใส่น้ำหนักขาย/แถม/ส่วนลด
3. **เซ็ต + ตัวเลือก / Add-on** — ราคาเซ็ต · สต็อกที่ตัดต่อเซ็ต · กลุ่มตัวเลือก “บังคับเลือก 1” หรือ “Add-on (+/-)” โดยแต่ละตัวเลือกมี +ราคา และตัดสต็อกจาก Pool ที่เลือก

## 6.2 จอจัดออเดอร์หลังร้าน (KDS) — iPad เครื่องที่ 2
1. เปิด URL เดียวกัน ▸ ตั้งค่า ▸ เครื่องนี้ ▸ ใส่ Google Sheets URL เดียวกับเครื่องขาย ▸ เลือก **🍳 จอจัดออเดอร์ (KDS)**
2. แตะหน้าจอ 1 ครั้งเพื่อเปิดเสียง (ข้อจำกัดของ iPad) — มีออเดอร์ใหม่จะมีเสียง “ติ๊ง” · ถ้าหน้าร้านยกเลิกบิลที่ยังทำไม่เสร็จ การ์ดจะ **กะพริบแดง + เสียงเตือน**
3. การ์ดเรียงจากเก่าสุด แสดงเลขคิว, เวลาที่รอ (เหลือง ≥ 5 นาที / แดง ≥ 10 นาที — ปรับได้), รายการ, ตัวเลือก, หมายเหตุ
4. กด **✓ เสร็จแล้ว** — กดผิดกด “ย้อนกลับ” หรือ “เรียกคืน” ในแถบขวา · แถบขวาแสดง **ยอดรวมที่ต้องเตรียม** ของทุกออเดอร์ที่ค้าง
5. เลือกหมวดที่ “ส่งเข้าครัว” ได้ที่ จัดการเมนู ▸ หมวดหมู่ · KDS ดึงคิวทุก ~6 วินาที (หน่วงประมาณ 3–10 วินาที) และสถานะ “เสร็จแล้ว” ใช้คิว Sync เดียวกับบิล (ส่งซ้ำอัตโนมัติถ้าเน็ตหลุด)

## 7. ใช้หลายเครื่อง (Multi-Device Cloud Sync)

ทุกเครื่องใช้ **Web App URL เดียวกัน** — Google Sheet เป็นศูนย์กลางของเมนู รูป สต็อก และบิล

**ตั้งค่าครั้งแรก**
1. **เครื่องหลัก** (iPad ที่ใช้จัดการเมนู): ตั้งค่า ▸ ใส่ URL ▸ ตั้ง **รหัสเครื่อง** เช่น `IPAD1` ▸ กด **☁️ อัปเดตเมนู/รูป/สต็อก ขึ้น Cloud** (ส่งทุกอย่างขึ้น ครั้งแรกครั้งเดียว)
2. **เครื่องอื่น** (iPad/PC/มือถือ): เปิดลิงก์แอป ▸ ตั้งค่า ▸ ใส่ URL เดียวกัน ▸ ตั้งรหัสเครื่องที่ **ไม่ซ้ำ** เช่น `IPAD2`, `PC1` ▸ กด **📥 ดึงเมนู/รูป/สต็อก ล่าสุดจาก Cloud** ▸ เปิดสวิตช์ **ซิงก์อัตโนมัติเมื่อเปิดแอป**

**การทำงาน**
- แก้เมนู/รูป/สต็อกที่เครื่องไหน → ส่งเฉพาะส่วนที่เปลี่ยนขึ้น Cloud ภายใน ~4 วินาที (สวิตช์ “ส่งการเปลี่ยนแปลงขึ้น Cloud อัตโนมัติ”)
- ขายของที่เครื่องไหน → บิลถูกส่งขึ้น Sheet และ **สต็อกบน Cloud ถูกตัดตามบิลนั้น** (คืนเมื่อยกเลิกบิล) — ไม่ตัดซ้ำแม้ส่งซ้ำ
- กด **ดึงจาก Cloud** → แอปส่งบิลและการแก้ไขที่ค้างของเครื่องนี้ขึ้นไปก่อน แล้วค่อยดึง จึงไม่มีข้อมูลหาย
- เครื่องที่เปิด “ซิงก์อัตโนมัติ” จะดึงข้อมูลใหม่ทุกครั้งที่เปิดแอป และเมื่อกลับมาที่แอปหลังพักเกิน 3 นาที (เมื่อตะกร้าว่าง)
- **ประวัติบิล ▸ ทุกเครื่อง (Cloud)** ดูยอดขายรวมทุกเครื่องของวันที่เลือก (บิลของเครื่องอื่นยกเลิกได้ที่เครื่องนั้นเท่านั้น)

> ⚠️ ปุ่ม **อัปเดตขึ้น Cloud (Push from Main)** เขียนทับข้อมูลบน Cloud ทั้งหมด รวมจำนวนสต็อก — ใช้จากเครื่องหลักเท่านั้น
> ชื่อร้านและคำโปรยซิงก์ไปทุกเครื่อง ส่วน URL, รหัสเครื่อง และสวิตช์ต่าง ๆ เป็นของแต่ละเครื่อง

ปรับวิธีชำระเงินได้ที่ `PAY_METHODS` ใน `app.js` · เมนูตั้งต้นสำหรับเครื่องใหม่อยู่ที่ `buildSeedCatalog()`

| ปุ่ม Sync ขึ้น Pending ค้าง | ดูหัวข้อ “รอส่งขึ้น Cloud” และ “ข้อผิดพลาด” ในหน้าตั้งค่า · ตรวจว่า Deploy โค้ด v2 แบบ **New version** แล้ว |
| Sync ขึ้น "ตอบกลับไม่ใช่ JSON" | Deploy ใหม่โดยตั้ง **Who has access: Anyone** และใช้ URL ที่ลงท้าย `/exec` |
| Sync ค้างในคิว | ตรวจ URL ▸ กด **ทดสอบ** ▸ ดูข้อความ error ในคิว ▸ ดูชีต `Sync_Log` |
| แถบแดง “เซสชันหมดอายุ” | กด **รีเฟรชเพื่อ Login ใหม่** ▸ อีเมล + OTP (ตั้ง Session Duration ยาวขึ้นได้ใน Zero Trust ▸ Access ▸ Applications) |
| “โดเมนนี้ไม่ได้อยู่หลัง Cloudflare Access” | เปิดจาก URL preview ที่ไม่ได้ใส่ใน Access — ใช้ URL หลัก หรือเพิ่ม `*.<โปรเจกต์>.pages.dev` ในแอป Access |
| “ยังไม่ได้ตั้งค่า GAS_URL / ACCESS_AUD …” | ใส่ตัวแปรใน Pages ▸ Settings ▸ Variables and Secrets ▸ แล้ว Retry deployment |
| “รหัสลับไม่ตรงกัน (SYNC_SECRET …)” | ค่า `SYNC_SECRET` ใน Cloudflare ต้องเหมือนใน Apps Script (Project Settings ▸ Script properties) |
| แอปไม่อัปเดตหลัง push | ตรวจว่าออนไลน์ ▸ กด 🔄 Update App Version ▸ รอ Cloudflare Pages deploy เสร็จ (แท็บ Deployments) |
| ฟอนต์ไม่สวยตอนออฟไลน์ครั้งแรก | เปิดแอปขณะออนไลน์ 1 ครั้งเพื่อให้ฟอนต์ถูก cache |
